# 调试、编译、烧录

本文按本仓库实际环境写：macOS + **ESP-IDF v5.1.2**，目标 **ESP32-S3**，Flash **16MB**。更细的接线与网页用法见根目录 `README.md`。

## 1. 加载 IDF 环境

每个**新终端**都要先 `export`，否则找不到 `idf.py`。

```bash
cd "/Users/zhouguan/Desktop/esp32/ESP32-S3"
. "$HOME/esp/v5.1.2/esp-idf/export.sh"
```

成功时会提示可以 `idf.py build`。工具链在 `~/.espressif/`，IDF 源码在 `~/esp/v5.1.2/esp-idf`。

## 2. 确认串口

CH340 一类转接在 macOS 上常见为 `/dev/cu.wchusbserial*`。先插上板子：

```bash
ls /dev/cu.*usb* /dev/cu.wchusbserial* 2>/dev/null
```

下文用 `PORT` 表示实际设备，例如 `/dev/cu.wchusbserial10`。

## 3. 配置（一般不用每次做）

芯片、Flash、分区已写在 `sdkconfig`：

| 项 | 当前值 |
|----|--------|
| 目标 | `esp32s3` |
| Flash | 16MB，DIO，80MHz |
| 分区表 | `partitions_4mb.csv`（factory 应用 4MB） |
| 监视波特率 | 115200 |

需要改菜单时：

```bash
idf.py menuconfig
```

Flash 大小：`Serial flasher config → Flash size` 必须与板子一致（本板 **16MB**）。若日志警告「检测到 16MB 但镜像头是 2MB」，就是这里设小了。

HTTP 头过长（手机 431）：`Component config → HTTP Server` 里 `Max HTTP Request Header Length` / `Max HTTP URI Length`（工程已设 2048）。

## 4. 编译

```bash
idf.py build
```

只刷新编译数据库（给 clangd 用，不链接固件）：

```bash
idf.py reconfigure
```

产物在 `build/`（已 gitignore）。`compile_commands.json` 也在这里；`.clangd` 已指定 `CompilationDatabase: build`。

**目录改名后**（例如从 `esp32-4` 改成 `ESP32-S3`），旧 `build/CMakeCache.txt` 会指向旧路径，`reconfigure` 会失败。处理：

```bash
rm -rf build
idf.py reconfigure
```

`idf.py fullclean` 在路径对不上时可能拒绝自动删目录，此时直接删 `build/` 即可。

首次构建会经组件管理器拉取 `espressif/led_strip` 到 `managed_components/`，需要能访问组件仓库。若提示缓存目录问题，保证 `~/Library/Caches/Espressif/ComponentManager` 可写。

## 5. 烧录与监视

编译 + 烧录 + 看日志（一条龙）：

```bash
idf.py -p PORT build flash monitor
```

只烧录（工程已编过）：

```bash
idf.py -p PORT flash
```

只看串口（固件已在板子上）：

```bash
idf.py -p PORT monitor
```

退出监视：**`Ctrl+]`**。

烧录结束后默认 **hard_reset**，板子会自己跑起来。日志标签可在监视里搜：

- `morse_ap`：`app_main` / 灯带初始化
- `mqtt_lan`：MQTT 测试发布
- Wi‑Fi / httpd 相关 IDF 日志

空闲灯应为黄色；HTTP 起来后手机搜 `ESP32-Morse`（开放热点，无密码；改名见 `components/wifi/include/wifi_softap.h`）。

## 6. 常见故障

**`Could not exclusively lock port` / `port is busy`**

串口被占用。先退出 `monitor`（`Ctrl+]`），关掉其它串口工具再 `flash`。

**烧录失败、无日志**

- 线是否数据口（不只充电）。
- `idf.py -p PORT monitor` 后按复位，看有没有输出。
- 下载波特率过高可在 `menuconfig → Serial flasher config` 降低后再试。

**改完代码灯/屏没变**

只改了头文件或图片数组后必须重新 `build flash`。`reconfigure` 不会把新固件写到板子。

**WS2812 不亮**

对照 `app_config.h` 的 `MORSE_LED_GPIO`（默认 48）。过亮有时反而不好辨色，可降 `MORSE_LED_BRIGHT_*`。

**打不开网页**

手机已连 `ESP32-Morse`；关掉「仅 WLAN 时禁止 HTTP」一类开关。本服务是 HTTP 不是 HTTPS。地址：`http://192.168.4.1/`。

**431 Request Header Fields Too Large**

手机 Cookie 把请求头撑爆。`sdkconfig` 已加大 httpd 头/URI 长度；仍出现再在 menuconfig 里加大。

**播放死机 / httpd 栈溢出**

`morse_http.c` 已加大 httpd 任务栈，JSON 缓冲用静态区。连续发送队列满会返回 `queue full`，不是死机。

**MQTT 发不出去**

- `MQTT_STA_WIFI_SSID` 必须非空，STA 要拿到局域网 IP（APSTA）。
- broker 须监听局域网（不能只绑 `127.0.0.1`）。
- 板子与 Mosquitto 同网段；URI 在 `app_config.h`。

**LCD 只有背光 / 偏色**

先核对 SDA=MOSI、SCL=CLK，且与 ESP32 共地、VCC=3.3V。参数基线见 `README.md` 与 `app_config.h`（`LCD_GAP_Y=20`、`LCD_SPI_MODE=3` 等）。轮廓对但像底片：查 `LCD_RGB565_LITTLE_ENDIAN`；红蓝反：切 `LCD_ST7789_BGR`。

## 7. 编辑器（clangd）

ESP-IDF 的 `compile_commands.json` 带 GCC 参数，Clang 会报 `Unknown argument`（如 `-mlongcalls`）。根目录 `.clangd` 已 `Remove` 这些选项，**不影响** `idf.py` 真编译。

改完 `.clangd` 或重新 `reconfigure` 后：命令面板执行 **clangd: Restart language server**，或重载窗口。

`.cache/clangd/` 是本机索引，不要提交（已在 `.gitignore`）。

## 8. 建议日常命令

```bash
. "$HOME/esp/v5.1.2/esp-idf/export.sh"
idf.py -p PORT build flash monitor
```

只改过配置、要刷新 clangd：

```bash
idf.py reconfigure
```

需要干净重配（目录搬迁、CMake 缓存坏了）：

```bash
rm -rf build && idf.py reconfigure && idf.py build
```
